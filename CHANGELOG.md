# Changelog

## 0.5.0

- Removed all dependency on **IR Control Hub Open Service**.
- Real A/C commands now use the thermostat's own `ir_send` / DP201 path.
- Added automatic IR learning from the regular Tuya IoT Core operation-log API:
  - `GET /v2.0/cloud/thing/{device_id}/logs`
  - event type `5` (command sending)
  - DP code `ir_send`
- Added reverse synchronization from IoT Core status-report logs:
  - `GET /v2.0/cloud/thing/{device_id}/report-logs`
  - legacy IoT-03 report-log fallback
- On startup the integration imports up to 100 recent `ir_send` commands from the previous 24 hours.
- While running it checks for new Smart Life IR commands every 60 seconds and stores them persistently in Home Assistant `.storage`.
- The integration stores the exact `ir_send` payload generated by Smart Life. It does not guess or synthesize raw IR data.
- Climate changes search the learned library for an exact mode + temperature + fan command and replay it through DP201.
- Power-off uses the learned `power_off` IR command.
- If an exact combination is not learned yet, the integration gracefully falls back to normal thermostat DPs instead of failing setup or throwing an unsupported-schema error.
- Added a **Learned IR commands** sensor.
- Added a **Sync IR library** button to re-import the last 24 hours immediately.
- Added attributes for `last_ir_key`, `last_ir_result`, `missing_ir_request`, and learned command count.
- Polling interval is 15 seconds for better device-to-Home-Assistant synchronization.
- No user-specific IR payload, `v_devid`, Device ID, or Access Secret is hard-coded.
